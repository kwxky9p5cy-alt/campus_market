# Frontend Contract

## 用户语言

主界面使用：在售、已预订、已售出、已下架、交易请求、面交、收藏、消息。

实现术语 `active`、`reserved`、`trade_request`、`conversation`、`RLS` 不作为普通用户的主文案。

## 页面模式

- 浏览：图片优先的商品网格，搜索状态写入 URL。
- 详情：先判断商品，再执行收藏、交易或卖家管理操作。
- 编辑：AI 结果只是可编辑草稿，提交前继续使用同一套表单验证。
- 交易：正式状态流和聊天分开呈现，不用聊天代替交易请求。
- 空、错、加载：每个异步主区域都提供稳定反馈和恢复动作。

## 硬约束

- 不把前端隐藏按钮当作权限控制；所有敏感数据依赖 Supabase RLS/RPC。
- 删除商品必须确认；完成交易必须确认已经面交。
- 图片类型、数量和大小在客户端与 Storage 同时限制。
- 移动端主操作必须在拇指可达区域，页面不得横向溢出。
- 图标按钮必须有可访问名称；表单必须有可见标签；焦点必须可见。
